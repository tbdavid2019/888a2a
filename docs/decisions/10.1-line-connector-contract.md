# LINE connector contract

Date: 2026-08-27

888a2a selects the LINE Messaging API as the first external connector for the
pilot because it matches the Taiwan/Japan customer path in the OpenSpec
decision record. The adapter remains behind Connector v1 and the durable inbox
and outbox.

## Inbound

- Verify the raw request body with HMAC-SHA256 and the channel secret against
  `X-Line-Signature` before JSON processing.
- Use `webhookEventId` as the installation-scoped deduplication identity.
- Preserve the event `timestamp`; LINE redelivery can arrive out of order.
- Acknowledge quickly after the authenticated event is committed to the
  tenant-scoped inbox. Normalize and route asynchronously.
- Map `unsend` to the canonical recall event. Keep unsupported operations
  explicit instead of simulating edits or reactions.
- LINE message edits are declared unsupported; an edit request must produce a
  delivery-divergence record instead of pretending that the platform message
  was updated. Group/room sources map to their external conversation ID, and
  join/leave events retain their lifecycle type for asynchronous routing.

## Outbound

- Use `/v2/bot/message/reply` when a valid reply token is present; otherwise use
  `/v2/bot/message/push`.
- Send a unique hexadecimal UUID in `X-Line-Retry-Key` for retry-safe API
  requests.
- Defer HTTP 408, 429, and 5xx responses using `Retry-After` when supplied;
  treat other 4xx responses as terminal delivery failures.
- Keep channel access tokens in the encrypted connector vault and never in
  canonical event payloads, logs, or audit records.

## Installation lifecycle

- Create the tenant-scoped installation metadata before accepting webhooks.
- Store the channel secret/access token only through the encrypted vault.
- Rotate credentials by replacing the ciphertext and key version atomically.
- Revoke the credential before deleting installation metadata; both operations
  are safe to retry and never return the former secret.
