## 1. Executive Summary & Objective

888a2a originated as a single-workspace, single-process collaboration platform supporting humans, Agents, Machines, and ACP runtimes. To support enterprise SaaS deployment, the system must transition to an **Organization-first, multi-tenant architecture**:
$$\text{Organization} \longrightarrow \text{Workspace / Project} \longrightarrow \text{Resources (Conversations, Agents, Tasks, Connectors, Approvals)}$$

This decision document establishes the authoritative baseline inventory of:
1. All database tables across `backend/manager/migration/` (migrations `0001` through `0028` and `LATEST.sql`).
2. Current flat API resource names and their target AIP-2338 hierarchical resource names.
3. Process-local realtime paths, memory caches, and non-authoritative components requiring durable outbox/event replacements.
4. Complete capability coverage verification against `proposal.md` and `design.md`.

## 4. Process-Local Realtime Paths & Concurrency Bottlenecks

An audit of the existing codebase identified six process-local mechanisms that rely on single-process memory or best-effort delivery:

```
+-----------------------------------------------------------------------------------+
|                        LEGACY IN-MEMORY BOTTLENECKS                               |
+-----------------------------------------------------------------------------------+
| 1. RoomHub (roomhub.RoomHub)           --> Ephemeral in-memory subscriber channels |
| 2. Long-Poll Manager (longPollMgr)     --> Ephemeral Go channels for HTTP polling  |
| 3. Command Watchers (commandWatcher)   --> In-memory output streaming dispatch     |
| 4. Nonce Replay Cache (NonceVerifier)  --> In-memory sync.Map (lost on restart)    |
| 5. Machine Dispatch (ActiveConns)      --> In-memory map (breaks multi-replica)    |
| 6. Activity & Push Background Workers  --> Uncoordinated in-memory cron loops     |
+-----------------------------------------------------------------------------------+
```

### 4.1 Detailed Audit of Bottlenecks

1. **`backend/manager/component/roomhub/`**:
   - Holds active subscriber channels in Go maps (`map[string]map[chan Event]struct{}`).
   - *Impact*: In a multi-replica Manager deployment, a message published on Replica A is invisible to a user connected via WebSocket/SSE on Replica B.
2. **`backend/manager/api/v1/long_poll_test.go` & `backend/manager/component/dispatcher/`**:
   - Uses local Go channels to hold long-polling HTTP requests until a message arrives or timeout expires.
   - *Impact*: Fails when load balancer distributes requests across stateless instances.
3. **`backend/manager/api/v1/command.go`**:
   - Real-time command output chunks (`command_output`) streamed to clients via local goroutine event dispatchers.
   - *Impact*: Client reconnecting to a different replica loses live chunk stream.
4. **`backend/manager/api/auth/` Nonce Replay Verification**:
   - Validates client nonces using an in-process LRU cache / mutex-guarded map.
   - *Impact*: Allows replay attacks across different Manager replicas.
5. **`backend/manager/api/v1/machine_connection.go`**:
   - Machine dispatch checks `activeConnections[machineID]` locally.
   - *Impact*: Commands destined for a Machine connected to Replica B cannot be dispatched from Replica A without shared routing.

## 5. Durable Architecture Replacement Strategy

To eliminate process-local vulnerabilities, 888a2a implements the following distributed architecture:

```text
[ Client (Web/Connector/A2A) ]
              │
              ▼
[ Stateless Manager Replicas (A / B / C) ]
       │                      │
       ▼                      ▼
[ PostgreSQL Outbox ]   [ WuKongIM Message Plane ]
       │                      │
       ▼                      ▼
[ Distributed Workers ] [ Monotonic Ordering & Push ]
```

1. **Transactional Outbox (`backend/manager/store/outbox.go`)**:
   - All state mutations (Machine assignment, Connector egress, Approval events, A2A tasks) commit to PostgreSQL in the same database transaction as business state.
   - Background workers claim outbox entries with `SELECT ... FOR UPDATE SKIP LOCKED`, guaranteeing at-least-once durable delivery across replicas.
2. **WuKongIM Distributed Message Plane**:
   - Offloads per-channel message ordering (`message_seq`), client deduplication (`client_msg_no`), presence, and multi-device offline synchronization.
   - Replaces in-memory `RoomHub` and long-polling.
3. **Monotonic Machine Assignment Log (`a2a888_machine_assignment_event`)**:
   - Assigns strictly increasing sequence numbers per Machine. Machines maintain a persistent `last_ack_sequence` cursor and replay on reconnect.
4. **Durable Distributed Nonce Store**:
   - Nonces are persisted with TTL in PostgreSQL / Redis, preventing cross-replica replay.
